# Agent instructions — Stellar Portfolio

This repository is Ariston Michael's personal portfolio. Prioritize correct, accessible, fast, recruiter-friendly work over decorative complexity.

## Before making changes
1. Read `docs/PROJECT.md` and the task-relevant docs.
2. Use `docs/ABOUT_ME.md` as the source of truth for personal facts. Never invent links, metrics, dates, or accomplishments.
3. Follow `docs/DESIGN.md` for appearance and `docs/ARCHITECTURE.md` for implementation.
4. Check the current code and git status before editing. Never overwrite uncommitted work.

## Development
- Work on `development` or a task branch; do not push directly to `main`.
- Preserve the GitHub Pages user-site URL and use a statically exportable application.
- Run appropriate lint, type checks, build, and tests after implementation; report actual results, never claim tests that were not run.
- Ensure keyboard access, contrast, semantic markup, responsive layouts, and reduced-motion support.
- Do not introduce credentials into the repository. Avoid unnecessary dependencies.
- Ask before destructive operations, branch deletion, merge to `main`, or public deployment.

## Continuity
- Update `docs/ROADMAP.md` when milestones are completed.
- Record consequential technical/design choices in `docs/DECISIONS.md` with date and rationale.
- Keep docs concise and in sync; mark unverified claims as TODO rather than guessing.
